# 固定弹幕标签体系设计

## 目标

让弹幕报告以稳定、可比较的主题分类呈现，同时保留模型对单条原话的细粒度解释。导出的工作簿需要提供可审计的标签明细、情绪趋势、主题统计和原话，并使主题图表不再被零散的自由文本主题占据。

## 范围

本设计只修改 `twitch-chat-workflow` 的语义标注数据契约、分析聚合、Excel 导出、测试和使用说明。不修改 Twitch 下载、音频转写项目或既有原始输入。

## 标签数据契约

每条已标注弹幕除既有 `sentiment`、`interest_signal` 外，必须具有以下字段：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `raw_topic` | 字符串 | 基于原话生成的简短中文描述；为空时写入“其他”。仅用于追溯。 |
| `report_topic` | 枚举 | 必须为：游戏内容、直播体验、主播表现、观众互动、技术问题、角色或剧情、其他。 |
| `content_type` | 枚举 | 必须为：游戏内容、直播互动、主播内容、技术与平台、日常话题、社区文化、其他。 |
| `message_type` | 枚举 | 必须为：评价反馈、提问求助、信息陈述、玩笑梗图、表情或刷屏、机器人通知、其他。 |
| `is_bot` | 布尔值 | 机器人或自动通知为 `true`，其他为 `false`。 |
| `needs_review` | 布尔值 | 语义不完整、讽刺或多主题歧义、低置信度时为 `true`。 |
| `confidence` | 枚举 | 必须为：高、中、低。 |

`topic` 字段由 `report_topic` 取代；不保留具有歧义的旧字段名。兼容读取旧标签 CSV 时，旧 `topic` 视为 `raw_topic`，并将 `report_topic` 安全归为“其他”。

## Codex 标注约束

Codex 的 JSON Schema 必须为全部新增字段声明类型和枚举，且禁止额外字段。提示词必须逐条要求：原始主题只描述原话，报告主题只能选择规定的七类；不确定时使用“其他”并标记人工复核；机器人消息标记 `is_bot=true` 且消息类型为“机器人通知”。

响应解析应拒绝缺字段、枚举外取值、重复或乱序的消息 ID。单一批次失败不得写入可复用批次文件。

## 聚合与工作簿

主题汇总、时间窗口主题趋势和主题 Top 10 图表一律按 `report_topic` 聚合。标签明细展示原始主题与报告主题及全部新增标签。原话页显示报告主题与原始主题，确保读者能从汇总回溯到模型判断与原话。

“主题”页的名称保持不变，但汇总列标题明确为“报告主题”；七种固定报告主题最多各出现一次，按数量降序排序。代表性原话仍从相应报告主题下挑选。

## 状态、复用与兼容性

标签批次的保存与复用使用新的 `MessageLabel` 完整数据形状。旧批次缺少新增字段时视为不可复用并重新标注；已完成的旧工作簿不被修改。阶段指纹继续包含配置与清洗输入，新的标注代码仅在重新运行标签阶段时生效。

## 测试与验收

测试覆盖：模型标签的枚举验证；不完整或枚举外的 Codex 响应被拒绝；标签 CSV 包含全部字段；分析按报告主题而不是原始主题归并；旧 CSV 的安全兼容归类；工作簿四个工作表展示新增列，且主题图表和汇总只使用固定报告主题。现有完整测试套件必须通过。
