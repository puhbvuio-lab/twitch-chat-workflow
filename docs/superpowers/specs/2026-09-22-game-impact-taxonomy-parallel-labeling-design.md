# 游戏影响标签与三路并行标注设计

## 目标

以游戏内容对直播效果的影响为主要研究对象，将每条弹幕归入固定的游戏影响一级、二级模块；未落入模板的内容统一归为“其他”。对 Sayu 全部 2,027 条弹幕使用当前 Codex 登录态重新标注，并通过三路批次并行缩短运行时间。

## 标签结构

保留 `raw_topic` 作为贴近原话的自由文本主题。新增或替换报告层字段为 `primary_module` 和 `secondary_module`。

一级模块固定为：剧情与世界观、战斗体验、探索与互动、其他整体兴趣、其他。

一级、二级映射必须严格如下：

| 一级模块 | 二级模块 |
| --- | --- |
| 剧情与世界观 | 电影化过场／演出高光 |
| 剧情与世界观 | 剧情内容／叙事情绪 |
| 剧情与世界观 | 整体剧情世界观感受 |
| 战斗体验 | BOSS 战 |
| 战斗体验 | 常规战斗 |
| 战斗体验 | 综合战斗感受 |
| 探索与互动 | 跑图与移动 |
| 探索与互动 | 调查与解谜 |
| 其他整体兴趣 | 角色兴趣 |
| 其他整体兴趣 | 整体美术与音声兴趣 |
| 其他整体兴趣 | 游戏整体兴趣 |
| 其他 | 其他 |

二级模块不得合并。主播表现、观众互动、机器人通知、技术问题、生活闲聊以及无法识别的内容在本版本中统一归为 `其他 / 其他`。无法可靠判断的记录同时设置 `needs_review=true` 和 `confidence=低`。

## 分类原则

模型先判断弹幕是否明确讨论游戏因素。若是，按照“具体优先、整体兜底”选择一个二级模块；若同时符合多个模块，选择主要评价对象，并将歧义写入复核原因。若不是或证据不足，则使用 `其他 / 其他`。

一级模块不允许独立自由生成，必须由二级模块的固定映射验证。Schema 负责枚举约束，应用层负责交叉映射约束。缺字段、枚举外取值、错误映射、重复或乱序消息 ID 均使该批次失败，不产生可复用缓存。

## 三路并行

每批 20 条，最多同时运行 3 个独立 Codex CLI 子进程。每批使用独立临时 Schema 文件和 `batch-XXXX.json`，成功批次立即原子写入，最终按批次号和原消息顺序合并。

并行调度必须满足：

- 同时运行的批次数不超过配置 `concurrency=3`。
- 单批失败不取消已经成功的批次。
- 超时、限流或临时服务错误只重试失败批次，并采用递增退避。
- 连续限流时允许本次运行动态降低到 2 路或 1 路，不改写用户配置。
- 重启后复用已完成且指纹、模型、字段契约、消息 ID 完全一致的批次。
- 最终 CSV 顺序与清洗输入顺序一致，不受完成先后影响。

并行只缩短耗时，不减少 token；失败重试可能略微增加消耗。

## 工作簿与人工复核

`标签明细`显示原始主题、一级模块、二级模块、内容类型、消息类型、机器人判断、复核状态和置信度。`主题`工作表分别提供一级模块汇总、二级模块汇总和按二级模块统计的 Top 10 图表。`情绪趋势`和`原话`继续保留。

另生成 `人工复核`工作表，收录 `needs_review=true`、低置信度以及不明确的 `其他 / 其他`记录。工作表包含稳定消息 ID、时间、原话、相邻上下文、模型标签、争议原因、人工最终标签、审核状态和人工备注。人工返回后以消息 ID 合并，验证固定映射，再生成 `弹幕分析_人工审核版.xlsx`；原始模型结果不被覆盖。

## 完整 Sayu 运行

使用 `D:/主播分析结果/弹幕数据/Sayu/02_弹幕/twitchchatdownloader_first_option.csv` 的全部 2,027 条记录，在新的独立输出目录运行，禁止复用旧标签契约下的批次。生成的运行数据和工作簿不提交 Git，只提交源代码、测试和文档。

预计 102 个批次，三路并行预计约 35～65 分钟；限流时可能延长。完成后验证记录数、固定映射、批次完整性、工作表结构、图表数据源和人工复核行数。

## 验收

- 2,027 条输入均有且仅有一条标签结果。
- 一级、二级模块全部满足固定映射，11 个二级模块保持独立。
- 非模板内容只进入 `其他 / 其他`。
- 并发峰值不超过 3，失败批次可独立恢复。
- 工作簿汇总与标签明细计数一致。
- 人工复核记录可通过消息 ID 安全回填并重新生成审核版工作簿。
- 完整自动化测试套件通过。
