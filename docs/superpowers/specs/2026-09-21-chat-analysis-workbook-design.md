# 弹幕分析工作簿设计规格

## 目标与成功标准

完善 Twitch 弹幕工作流，使其能够使用当前机器已保存的 Codex CLI 登录态完成逐条语义标注，并在全部标注成功后生成一个适合人工审阅的 `弹幕分析.xlsx` 工作簿。

成功标准：给定一个有效 VOD 弹幕任务，完整流程可断点续跑地生成标签明细、情绪趋势、主题汇总与趋势、原话追溯四类结果；工作簿中的每个汇总结果都能追溯到逐条弹幕；任何标注批次失败时不生成不完整工作簿。

## 总体数据流

```text
raw_chat.jsonl
  → clean_chat.csv
  → Codex CLI 批次标注
  → labeled_chat.csv + batch-*.json
  → 情绪/主题聚合
  → 弹幕趋势.csv + 弹幕趋势.json + 弹幕分析.xlsx
```

现有 CSV/JSON 机器可读产物继续保留。Excel 是新增的人类审阅产物，不替换现有数据接口。

## Codex 登录态标注器

### 调用方式

新增默认 `codex_session` provider，通过子进程调用：

```text
codex exec --ephemeral --output-schema <schema-path> -
```

`codex exec` 默认复用当前机器已保存的 Codex CLI 登录认证。弹幕批次及标注指令通过标准输入传入，最终结果通过临时输出文件或标准输出读取。项目不得读取、复制、记录或提交 Codex 的认证文件和访问令牌。

### 结构化输出

每条标签必须包含：

- `message_id`：与输入稳定 ID 完全一致。
- `sentiment`：仅允许 `positive`、`neutral`、`negative`。
- `topic`：简洁、可汇总的中文主题短语；无明确主题时使用 `其他`。
- `interest_signal`：布尔值。

提示词要求基于弹幕原话和可配置的相邻上下文判断，不臆造主播身份、事件或未在文本中出现的事实。相同含义的主题应尽量使用稳定名称。

### 批次、校验与恢复

- 按配置的 `batch_size` 稳定分批，保留现有批次号。
- 每批输出使用 JSON Schema 限制结构。
- 返回条数、`message_id` 顺序、唯一性和枚举值必须与输入一致。
- 成功批次写入 `batch-XXXX.json`，并参与阶段状态产物清单。
- 重试时可复用输入指纹一致且校验通过的成功批次，只重新执行缺失或失败批次。
- Codex CLI 不存在、未登录、超时、退出码非零、输出不是合法 JSON、结构不合规、缺失、重复或乱序时，标注阶段失败并保持可重试。
- 错误摘要不得包含认证数据或完整提示词；可保留退出码和经过长度限制的安全诊断。

## 工作簿

### 文件与生成条件

最终文件固定为：

```text
04_chat_trends/弹幕分析.xlsx
```

使用 Python `openpyxl` 在进程内生成。先写同目录临时文件，完成校验后原子替换最终文件。只有全部弹幕标注成功且 `labeled_chat.csv` 完整时才生成工作簿；失败时删除本次临时文件，不覆盖此前完整产物。

### 工作表顺序与内容

#### 1. 标签明细

每条已标注弹幕一行，按时间和稳定消息 ID 排序。字段：

- 时间（秒）
- 时间（毫秒，源数据提供时）
- ISO 时间（源数据提供时）
- 用户
- 清洗文本
- 原话
- 情绪
- 主题
- 兴趣信号
- 编码警告
- 标注服务
- 标注模型
- 批次号
- 消息 ID

启用表头筛选、冻结首行、文本自动换行和适当列宽。原话完整保留，不能被清洗文本替换。

#### 2. 情绪趋势

按 `aggregation.interval_seconds` 生成半开时间窗口，空窗口保留零值。字段：

- 开始秒、结束秒
- 弹幕数、独立用户数
- 正面/中性/负面数量
- 正面/中性/负面占比
- 兴趣信号数

工作表上方放正面、中性、负面占比折线图。图表横轴为时间窗口，纵轴为 0%–100%，数据源直接引用该表趋势数据。

#### 3. 主题

上半部分为主题汇总，每个主题一行：

- 主题
- 弹幕数量、占比
- 首次出现秒、末次出现秒
- 正面/中性/负面数量
- 代表性原话 1、2、3

代表性原话按时间顺序从该主题中选择前三条非空、去重原话，不进行模型二次概括。主题数量 Top 10 柱状图按数量降序；数量相同时按主题名称稳定排序。

下半部分为“时间窗口 × 主题”趋势明细：

- 开始秒、结束秒、主题
- 弹幕数量、主题在该窗口内的占比
- 正面/中性/负面数量

#### 4. 原话

按时间和消息 ID 排序，字段：

- 时间（秒）
- 用户
- 原话
- 主题
- 情绪
- 消息 ID

该表用于快速回看和溯源，不重复编码修复、provider 等审核字段。

### 格式规范

- 使用中文工作表名和中文表头；机器可读 CSV/JSON 字段保持英文。
- 标题和表头采用一致的深色填充与浅色文字；数据区保持克制、可读。
- 所有明细区启用自动筛选并冻结表头。
- 秒数使用数值类型，占比使用 Excel 百分比格式，布尔值显示为中文“是/否”。
- 长文本列自动换行并限制合理宽度；不得因列宽造成大量截断或 `####`。
- 图表不得覆盖数据表，且必须引用实际有数据的范围。

## 聚合逻辑

情绪趋势沿用现有固定时间窗口语义。主题聚合只使用完整标注结果：空主题在写入标签时规范为 `其他`；不按大小写或模糊相似度自动合并不同主题，避免错误归并。主题占比的分母为对应整体或时间窗口内的已标注弹幕总数。

当没有弹幕时，工作簿仍生成四个带表头的工作表；趋势图和主题图不创建空数据系列，并在相关工作表显示“没有可分析的弹幕”。

## CLI 与状态管理

- `label` 在启用标注且未显式注入 provider 时，根据 `labeling.provider` 创建 `codex_session` provider。
- `aggregate` 要求存在完整的 `labeled_chat.csv`；若标注未启用或未完成，则拒绝生成分析工作簿并给出可操作错误。
- `run` 继续按 acquire → clean → label → aggregate 顺序执行。
- 聚合阶段状态的预期产物加入 `弹幕分析.xlsx`，缺失时触发安全重跑。
- 输入指纹包括完整标签文件、聚合间隔和工作簿格式版本，确保布局或算法升级后重新生成。

## 配置与依赖

- 新增 `openpyxl` 运行依赖，限定兼容版本范围。
- `labeling.enabled` 必须为 `true` 才能生成工作簿。
- `labeling.provider` 默认继续为 `codex_session`。
- 可配置 Codex 命令路径和批次超时，但不允许在配置中保存认证令牌。
- 现有 provider 注入接口保留，单元测试和其他调用方可继续提供离线 provider。

## 测试与验收

- Provider 单元测试：命令参数、标准输入、JSON Schema、成功解析、退出失败、超时、无效 JSON、条数/顺序/唯一性校验及诊断脱敏。
- 恢复测试：已完成且输入指纹一致的批次不重复调用；失败批次可重试。
- 聚合测试：情绪空窗口、主题数量/占比、稳定排序、代表性原话去重和时间窗口主题趋势。
- 工作簿测试：文件名、四个工作表及顺序、表头、冻结窗格、筛选、百分比格式、原话完整性和两个图表存在。
- 原子写入测试：生成失败不留下半成品，也不覆盖此前完整工作簿。
- CLI 测试：默认创建 Codex provider；未登录或未完整标注时不生成工作簿。
- 完整离线烟雾测试：使用假的 Codex 执行器从清洗弹幕运行到 `弹幕分析.xlsx`。
- 运行完整 pytest 测试集，且真实网络、真实 Codex 登录和模型调用不作为自动测试前提。

## 非目标

- 不读取或管理 Codex 认证文件。
- 不新增 OpenAI API Key 标注路径。
- 不自动推断说话人身份或主播/观众角色。
- 不对不同主题执行模糊合并或聚类。
- 不将 Excel 公式作为核心业务计算来源；工作簿展示已经验证的 Python 计算结果。
- 不改动音频转写项目。
